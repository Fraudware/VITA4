# VITA4 changelog

For the current feature list see [README.md](README.md).

## Releases

| Version | Changes |
|---|---|
| 1.0.0 | **First public release.** Picture, sound and DualShock 4 controls over one USB cable; touchpad with tap shaping and a fresh touch per tap; stick dead zone; Smooth / TV scaler / Sharp / FSR upscaling; Picture resolution Full / Fast; Stats overlay; L3 shortcuts. Low lag Off by default. Identical to development build 2.0 |

## Development builds

The builds below were private test builds made before the public release,
numbered 1.00 to 1.40 and 2.0. Oldest first; rows marked "undone" were
experiments rolled back after testing on real hardware.

| Build | Changes |
|---|---|
| 1.00 | First build (PS4 USB library only - could not see the Vita) |
| 1.01 | Raw-USB (GoldHEN) path - **known-good reference**, Vita detected and working |
| 1.02 | Custom splash screen |
| 1.03 | Custom home-screen tile |
| 1.04 | Launch background = splash picture |
| 1.05 | Synced with the VITA5 beta of 2026-10-07: updated shared USB core (short-packet video fix, preserved read errors, audio EBUSY fix, idle re-commit); controller policy of the new VITA5 bridges (100 ms hold refresh, one neutral on idle/menu/exit, touch keepalive 250 ms, release on target switch, front touchscreen default); "Controller to Vita" on/off and VITA5's scripted Input test in the menu; Stats shows reports sent instead of the misleading "linked"; bundles Vita plugin input_receiver v2.0.3 |
| 1.06 | Synced with the VITA5 beta 2026-10-07-2: **Upscale** setting Off / Sharp / FSR (AMD FSR 1.0 EASU + RCAS, off by default, saved); **L3 + D-pad Left/Right** cycles it with an on-screen label; **L3 + D-pad Up** switches full screen / windowed; while L3 is held, L3/R3 and the D-pad don't reach the Vita; shortcuts card next to the menu |
| 1.07 | Fix for 1.06 crashing on launch: the upscaler (about 41 MB and 5 threads) is now only set up while Upscale is on and released when it's turned off; if there isn't enough memory it switches Upscale off with a message instead of crashing; the opening splash image is freed after it fades; free memory is written to the log |
| 1.08 | Crash hunting for Upscale: if VITA4 stops while upscaling, the next launch switches Upscale off and shows the last run's log on the waiting screen (triangle); every upscaler step is logged; threads are created with checked, explicit stacks (a thread that can't be made is skipped instead of crashing); memory is committed up front; the upscaler uses SSE instead of AVX |
| 1.09 | **Fix for the Upscale crash** (and likely the 1.06 launch crash / 1.08 stuck splash): the toolchain's malloc never locks for PS4 system threads, so threads allocating at the same time corrupted memory. Every allocation now goes through one lock (`src/malloc_lock.c`, linker `--wrap`) |
| 1.10 | Upscale speed: render threads are pinned to separate CPU cores (main thread core 0, render helpers 1-3, upscaler 1-5); on the PS4 new threads can inherit a single core, which made the "parallel" upscaler run one band at a time. The log shows each band's core and time for the first frames |
| 1.11 | **Upscale about 3x faster.** FSR's edge-aware upscaling (EASU) and sharpening (RCAS) now run on brightness (luma) only, with colour scaled smoothly from the Vita's half-resolution colour plane (4:2:0 video has no finer colour detail); grey pictures match VITA5's shaders and smooth colour matches within one level. The 12-tap kernel's maths is rearranged (fewer multiplies, FSR-style fast reciprocals), 8 pixels per instruction (AVX), and areas where the 4 nearest pixels are within one level skip the kernel (EASU's own clamp makes the result the same). Six cores upscale, and the finished picture is copied to each screen buffer only once |
| 1.12 | From AMD's FSR 2.2.1 source: a **Sharpness** setting (Off / Low / Medium / High / Max) using FSR 2's slider mapping (sharpness s -> 2 - 2s stops of RCAS; Off skips the sharpening pass and is faster), and FSR 2's noise-aware sharpening (`FSR_RCAS_DENOISE`) so fine grain and dithering are amplified about half as much. Max is VITA5's strength and the default. FSR 2's temporal parts (motion vectors, depth, jitter) don't apply to a video feed and are not used |
| 1.13 | **Smooth** upscale mode: light sharpening at the Vita's size plus 2x bilinear, in whole-number byte SIMD (16 channels per instruction) straight into the screen - about 16x cheaper than FSR, full frame rate, no added delay; within one level of exact bilinear. **TV scaler (test)**: hands the PS4's display hardware a 960x544 picture to scale (falls back to Smooth with a message if the PS4 refuses). Upscale order is now Off, Smooth, TV scaler, Sharp (slow), FSR (slow); Sharpness also sets Smooth / TV scaler strength |
| 1.14 | **Upscale cycling**: scrolling right no longer sticks at Smooth - once the PS4 refuses the TV scaler it is skipped (and shown as not supported). **Steadier touchpad**: a DS4 touch that drops out for a moment (light touches do) no longer breaks a drag or turns a tap into a double tap; quick taps are held long enough for games to see them; a controller read error no longer counts as lifting the finger; the pad's outer strip now reaches the Vita screen's edges and corners |
| 1.15 | **Touch taps select again.** The DS4 pad's reading wobbles under a still finger (more as it lifts), and the Vita treats any movement past a few pixels as a scroll, so 1.14's longer-held taps only highlighted options. Each finger now stays pinned where it landed until it moves about 2.5% of the pad away (touch slop, as on phones); scrolling and dragging follow freely after that |
| 1.16 | **Controller polish.** L1/R1 now press the Vita's L/R shoulder buttons (SceCtrl LTRIGGER/RTRIGGER - before, they sent only the PS TV's extra L1/R1 codes, which handheld games ignore, so only L2/R2 worked as L/R). Stick dead zone (10/128, rescaled) so resting drift no longer creeps; triggers ignore resting noise. Stick values now reach the Vita exactly (the old mapping pulled everything below centre one step up/left). Button presses are sent immediately, never queued behind stick updates; one-step stick flicker is batched |
| 1.17 | **Controls restored to 1.15.** 1.16's controller changes (L1/R1 also sent as the Vita's L/R, stick dead zone and remapping, new send timing) made the controls misbehave on real hardware, so they are all undone; buttons, sticks and timing are exactly as in 1.14/1.15. The touchpad fixes from 1.14/1.15 stay |
| 1.18 | **Right stick no longer sluggish.** The Vita plugin keeps each report's stick position for only one Vita input sample (1/60 s; buttons last half a second), and a stick held still was only re-sent every 100 ms - so between refreshes the Vita saw it centred and a held camera turn ran about 1/6 of the time. While a stick is off centre, the report is now re-sent every 12 ms. Nothing else changed |
| 1.19 | **Touchpad presses select again.** The touch handling is back to exactly what 1.13 did (no steadiness filter, no edge margins, a failed controller read counts as a lift) - the 1.14/1.15 touch changes made taps only highlight options. The 1.18 right-stick fix and everything else stay as they were |
| 1.20 | **Touch taps for games.** New menu row *Touch taps*: **Steady** (default) holds every tap for at least 80 ms so a game reading the screen once per frame sees it, keeps a gap of 50 ms between taps so quick taps stay separate, and keeps the touch exactly where it landed until the finger really moves (a lift-off jump no longer turns a tap into a tiny drag, which games cancel - "only highlights"). **Slow games** holds 130 ms / gap 80 ms. **Raw** is 1.19 exactly. Sticks, buttons, upscale unchanged |
| 1.21 | **A fresh touch id for every tap** (Steady / Slow games). The Vita plugin labels its two touch slots with fixed ids, while a real Vita gives each new finger contact a new id; games that follow touches by id (Killzone Mercenary's pause menu) took a new tap for the old touch carrying on, so options only highlighted. Each new press now uses the other slot, so back-to-back taps reach the game as different ids. PS4 side only - no plugin change. Raw unchanged |
| 1.22 | **Less picture lag + a lag readout.** The screen used to be drawn right after each refresh, so a Vita frame that arrived just after that point waited almost two refreshes. Now VITA4 waits for the next Vita frame and draws it the moment it arrives (as late as still makes the next refresh), saving up to ~16 ms. Stats has a new line: *pad* (controller change to report on the USB, incl. the 4 ms polling wait on average), *USB picture* (one frame over the cable; sceUsbd path only) and *to screen* (frame arrived to shown). The game's own lag and the TV's are not measurable from the PS4 |
| 1.23 | **No more judder from the 1.22 lag cut.** 1.22 timed each draw from the *average* draw time with a 3 ms margin, so a slower draw sometimes missed its refresh and that picture showed one refresh late (motion and camera turns stuttered). The timing now uses the slowest recent draw plus 4 ms, and every missed refresh moves drawing earlier. New menu row **Low lag** (On by default; Off = 1.21 timing) and a *late* count (missed refreshes) in Stats |
| 1.24 | **Controls exactly as in 1.21.** The controller code (DualShock 4 reading, button/stick reports, timings) is byte-for-byte 1.21 again: the only change to it since then, the "pad" lag measurement in the input loop, is removed (Stats shows *USB picture* and *to screen* only). Touchpad (Touch taps, fresh id per tap) and picture timing (Low lag, 1.23) unchanged |
| 1.25 | Controller thread on its own core with top priority (did not fix the right stick; undone in 1.28) |
| 1.26 | Held stick re-sent every 6 ms, Input/s in Stats (did not fix it; undone in 1.28) |
| 1.27 | Vita plugin v2.0.4 holding sticks for 16 samples (did not fix it; undone in 1.28 - back to v2.0.3) |
| 1.28 | **Right stick fixed: Low lag is Off by default.** Testing showed the right-stick stutter (camera turns stopping part-way in Killzone Mercenary) came from Low lag's picture timing, not the controls: with Low lag Off it is smooth. Low lag now defaults to Off and earlier saved settings are reset to Off (it stays in the menu). Everything else is 1.24: controller code exactly as 1.21, Vita plugin v2.0.3, touchpad (Touch taps) unchanged |
| 1.29 | **Low lag, rebuilt.** The old Low lag drew each frame "as it arrived, unless too late" - a moving cut-off that sent frames near it to one refresh or the next at random, so motion stopped and started. Now VITA4 measures where in each refresh the Vita frames arrive and draws at one fixed moment just after them (pacing.c), so frames go out at the next refresh at an even pace - up to one refresh (~16 ms) less lag than Off. When arrivals are too irregular, or there is no time left to draw, it uses Off's timing. The moment only moves when it is >2 ms off. Low lag is On by default again (earlier choices reset); Stats shows the draw moment and how wide the arrivals are. Controls (1.21), plugin v2.0.3 and touchpad unchanged |
| 1.30 | **Picture size: Fast 480x272 (less lag).** New menu row. The Vita also offers its picture at 480x272, a quarter of the data of 960x544, so each frame crosses the USB cable in roughly a quarter of the time (~6 ms instead of ~23 ms): less lag, softer picture. Switching restarts the stream. If the Vita doesn't send that size the picture stays full size. Default Full. On the user's setup Low lag (1.29) reported frame arrivals 11-14 ms wide - too irregular for a fixed draw moment - so it falls back to Off timing; smaller frames may arrive evenly enough for it to work |
| 1.31 | **Less sound delay.** Sound came off the USB in 32 ms batches (32 x 1 ms packets per transfer) and the play-out backlog could grow to ~85 ms before being cut back to ~32 ms, so gunfire was heard well after the Vita. Now: 8 ms batches (12 transfers queued so it never runs dry), playback starts after ~11 ms, and above ~27 ms the backlog is trimmed 1 ms at a time (inaudible) instead of in one jump. Stats shows the sound backlog next to "Sound on" |
| 1.32 | **Right stick fixed again; menu renames.** 1.31's smaller sound batches meant four times as many USB audio transfers, which held up the controller's reports on the same link - the right stick stopped part-way through turns again (with Low lag On or Off, either resolution). Audio over USB is back to 1.29/1.30 (4 x 32 ms). Kept, without touching USB: the sound backlog is now capped at ~48 ms (was 85 ms), trimmed 1 ms at a time. Menu: "Picture" is now **Picture size**, "Picture size" is now **Picture resolution** |
| 1.33 | Upscale on Picture resolution Fast via a 2x pre-scale (undone in 1.35) |
| 1.34 | Controller read-glitch bridging, faster pre-scale (undone in 1.35) |
| 1.35 | **Back to 1.32** at the user's request: everything is exactly 1.32 (incl. the "Picture size" / "Picture resolution" names); 1.33's pre-scale and 1.34's changes are removed |
| 1.36 | Frame-rate cap for Fast 480x272 (froze the app's input when a game started; undone in 1.37) |
| 1.37 | **Consolidated "known good" build.** 1.35 (= 1.32): controller code as 1.21, Touch taps (fresh id per tap), Low lag 1.29 (fixed moment; falls back to Off timing when arrivals are irregular, as on Full), Smooth upscale, 1.29 audio transfers with the 1.32 backlog cap, "Picture size" / "Picture resolution" names. **Picture resolution is locked to Full 960x544**: at Fast 480x272 the Vita re-sends ~240 frames a second (ignoring the requested 60) and overloads itself and the cable, and slowing it from the PS4 stalls its controller handling. Saved Fast choices reset to Full. Left out: 1.31 small audio batches, 1.33 pre-scale, 1.34 glitch bridging, 1.36 frame cap |
| 1.38 | 1.37 + a Stats line showing the raw DualShock 4 stick readings (0..255, 128 = centre), to check the user's report that turning right is faster than the other directions. VITA4's stick conversion is symmetric (full right reaches the Vita as 255, full left as 0); nothing else changed |
| 1.39 | **Stick dead zone.** The user's DualShock 4 read 135/132 and 127/125 at rest instead of 128/128, so the Vita saw a constant small push - a camera that turned right faster than left. Readings within 12 of centre (round, so diagonals stay smooth) now count as centre, and the rest of the range is stretched so full pushes still reach 0 and 255. Both sticks; menu **Stick dead zone** (On by default). Stats still shows the raw readings |
| 1.40 | **Picture resolution Fast 480x272 available again**, exactly as in 1.30-1.32 (the user ran it fine then; the one "no sound / choppy" session that led to the 1.37 lock happened on code identical to 1.32 and may have had another cause). Default stays Full. Everything else is 1.39 |
| 2.0 | 1.40 with Low lag Off by default (saved choices kept). New README with features, setup, menu reference and known issues; this changelog split out of it. Published as **1.0.0** |
